# README 编写技术规范与实现方案

## 一、整体定位

README 定位为图书**综合入口文档**，承担三个职责：

| 职责 | 内容 | 优先级 |
|------|------|--------|
| 图书概述 | 书名、副标题、核心理念、金句 | P0 |
| 作者简介 | 姓名、头衔、经历、其他著作 | P0 |
| 目录索引 | 42 章结构化目录，可点击跳转 | P0 |

---

## 二、目录索引与导航功能

### 2.1 结构化目录

按 11 个部分分组，每章含编号、标题、双链接：

```markdown
### 第一部 · 知识贬值与搜商崛起
| 章节 | 标题 | 在线阅读 | 源文件 |
|------|------|----------|--------|
| 01 | 你真正缺的可能不是知识F | [📖 阅读](url) | [📝 源码](url) |
```

### 2.2 导航机制设计

**GitHub Markdown 限制**：不支持 JavaScript，无法实现动态上一章/下一章。

**解决方案**：双链策略——每个章节提供两个入口：

| 链接类型 | 目标 | 体验 |
|----------|------|------|
| 📖 在线阅读 | GitHub Pages 阅读页 | 沉浸式阅读，含上一章/下一章按钮 |
| 📝 源文件 | GitHub 仓库 Markdown | 直接查看原始内容 |

> 上一章/下一章的顺序导航在**在线阅读页**中实现（网站已内置），README 提供入口。

### 2.3 锚点跳转

README 内部目录通过 GitHub 自动生成的锚点实现跳转：

```markdown
- [第一部](#第一部--知识贬值与搜商崛起) → 跳转到本部目录
```

## 三、阅读体验优化

### 3.1 排版设计

- **表格化目录**：结构清晰，信息密度高
- **Emoji 图标**：📖（阅读）、9F📝（源码）、✨（金句）增强可读性
- **分隔线**：章节间用 `---` 分隔
- **引用块**：金句用 `>` 突出
- **部分折叠**：11 个部分用 `###` 标题，GitHub 自动生成侧边导航

### 3.2 交互设计

- 目录表格的链接直接打开新页面
- 在线阅读链接指向 `read.html?chapter=XX`，自动定位到对应章节
- 源文件链接指向 GitHub Markdown 渲染页面

## 四、实现方式

### 4.1 适用平台

| 平台 | 支持 | 说明 |
|------|------|------|
| **GitHub** | ✅ 最佳 | 原生 Markdown 渲染，表格+锚点+链接 |
| GitLab | ✅ | 类似 GitHub |
| VS Code | ✅ | 预览支持表格和链接 |
| Typora | ✅ | 本地编辑预览 |

### 4.2 链接生成规则

```
在线阅读：https://chandler-song.github.io/search-intelligence/read.html?chapter={id}
源文件：  https://github.com/Chandler-Song/search-intelligence/blob/main/books-docs/{file}
```

### 4.3 优缺点

**优点**：
- 零依赖，纯 Markdown，任何平台可渲染
- 双链策略兼顾"在线阅读体验"和"源码可追溯"
- 表格目录信息密度高，扫读效率好

**缺点**：
- 42 章表格较长（可通过部分折叠缓解）
- GitHub Markdown 不支持动态导航（需跳转到网站）
- 锚点跳转依赖 GitHub 自动生成规则

## 五、方案对比

| 方案 | 实现方式 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| **A. 表格双链（推荐）** | README 表格 + 网站/源码双链 | 信息全，体验好 | 表格较长 | 本项目 |
| B. 纯列表锚点 | `- [章节](#锚点)` 列表 | 简洁 | 无外部跳转 | 短文档 |
| C. 单文件全量 | 所有章节内嵌 README | 一次加载全部 | 文件巨大，不可维护 | 小文档 |
| D. Wiki 方案 | GitHub Wiki 多页面 | 模块化 | 需额外维护 | 大型文档 |

**本项目选择方案 A**：README 作为索引入口，阅读体验由已部署的网站承担。
